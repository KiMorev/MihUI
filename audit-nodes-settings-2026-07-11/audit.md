# План визуального обновления: «Ноды» и «Настройки»

Дата аудита: 11.07.2026

## Ноды

- Сохранить карточную модель и отдельный блок текущего выбора в группах.
- Собрать заголовок, оперативную сводку и «Обновить» в одну верхнюю строку.
- Сводку сделать содержательной: доступно / всего, недоступно, время последнего обновления.
- Фильтры оформить компактной рабочей панелью: поиск остается первым, остальные фильтры визуально вторичны; при активных фильтрах показывать их количество и действие «Сбросить».
- Ясно разделить «Текущий выбор в группах» и «Все ноды».
- Сохранить существующую сетку карточек, флаги, ярлыки протокола, состояния, задержки и UDP.
- Для пустого и ошибочного состояния убрать впечатление заполненной формы: оставить сводку причины и одно действие «Повторить».

## Настройки

- Оставить одну страницу без вкладок.
- «Интерфейс» сделать компактным блоком пользовательских предпочтений.
- «Happ Decoder» переименовать в «Интеграция Happ Decoder» и добавить понятный статус: настроено / настроено частично / не настроено.
- Заменить технические имена полей на пользовательские: «API-ключ», «Адрес API», «Локальная команда», «Тайм-аут», «Резервный URL». Переменные `MIHUI_*` оставить вторичной подсказкой.
- API-ключ отображать как пароль с отдельным действием показа.
- Сгруппировать параметры по способам декодирования: облачный API, локальный декодер, удаленный резерв.
- «Сохранить» делать основной кнопкой только при несохраненных изменениях; «Перечитать» оставить вторичным действием.
- Показывать состояние изменений внутри блока интеграции, не смешивая его с изменениями YAML в верхней панели.

## Границы итерации

- Меняется визуальная структура и формулировки, существующая логика API и фильтрации сохраняется.
- Изменения синхронизируются в `index.html`, `styles.css`, `app.js` и самодостаточном `mihomo-editor.html`.
- Проверяются заполненное, пустое, ошибочное и узкое состояния.
